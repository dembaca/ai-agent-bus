Step 4 of [#151](https://github.com/dembaca/ai-agent-bus/issues/151), the handler half — the route is registered with the bridge's signing key in step 3's PR.

**What it does**

- `services/bridge/internal/release`: `GET /register/v1/release` (a `HEAD` too; every other method `405` with `Allow: GET, HEAD`), the registrar's record so a host's `selfupdate`/`attest` reads it unchanged — compact JWS, header `{"alg":"EdDSA","typ":"mm-agent-release+jwt","kid":…}`, claims `signers` (1–16 distinct `ssh-ed25519` keys, canonical), `version` (`v<x.y.z>` or `latest`, optional: keys only means no target), `set_at_ms` (the bridge's start), `iat`, `exp` (an hour later). `Cache-Control: no-store`. Nothing set: 404 `{"error":"no release set"}`, the registrar's exact body.
- It rides on `internal/registrar/core` rather than re-deriving it: `ParseReleaseSigners` (canonical form, duplicates, strict base64, blob types, 1–16), `ValidReleaseVersion` (no leading zeros), `Attestor.SignRelease`, and `core.Kid` — the hosts' own scheme (`base64url(sha256(raw public key))[:16]`), so a pinned set finds it.
- The signing key is step 3's `core.Attestor`; this package reads no key file. **The key file's own checks (owner-only mode, seed/key agreement) are step 3's** (`CB_BRIDGE_SIGNING_KEY_FILE`), as the coordinator ruled.
- A target without keys and a zero `set_at` are refused.

**Tests**

- `internal/release`: the record verifies through `core.VerifyRelease` with the right claims and times; `405` for POST/PUT/DELETE, `HEAD` served; the exact 404; the settings' negative cases (an `ssh-rsa` key, a duplicate, `0.103`, `v01.2.3`, a target without keys, a zero `set_at`).
- **Cross-language, pinned on both sides:** `mcp/tests/testdata/release_record.txt` is asserted by a Go test (a change to what this code signs fails) and verified by `mcp/tests/test_release_record.py` through the hosts' own `attest.pinned` (the pin derives the kid from the raw key) and `attest.verify_release`, plus a wrong-pin refusal.

`go test ./internal/release`, the Python test, `go vet`, doc-check and arc42-lint pass.
